# 07 — 控制面与三种并行

本文说明 v4 **控制 / 调度**如何承载 DP、TP、PP，以及三者为何分叉点不同。
策略与硬件背景见 [00-并行环境.md](00-并行环境.md)；**ZMQ / Gloo / NCCL 为何并用**见 [08-通信通道.md](08-通信通道.md)；NCCL 原语见 [集合通信.md](集合通信.md)。

## 1. 决策树（先读这个）

```
Engine(config)
  └─ make_client(dp_size)
        │
        ├─ dp == 1 ──► InprocClient ──► EngineCore
        │                                  └─ create_executor(tp, pp)
        │                                        ├─ tp=pp=1 → UniprocExecutor
        │                                        └─ else    → MultiprocExecutor
        │                                                      (Gloo 广播 + NCCL)
        │
        └─ dp  > 1 ──► MPClient
                         ├─ 副本 0：独立 EngineCore（dp 归 1，自有 NCCL world）
                         ├─ 副本 1：…
                         └─ ZMQ round-robin 分发请求 / 汇总输出
```

| 配置 | 谁做调度 | 控制通道 | 计算通信 | world |
| --- | --- | --- | --- | --- |
| 单卡 | 1× Scheduler | 无 IPC | 无 | 1 |
| TP / PP | 1× Scheduler，同一份 schedule 广播 | Gloo `ControlChannel` | NCCL（TP 集合 / PP P2P） | `tp×pp` |
| DP | **每副本** 1× Scheduler | ZMQ | 副本间无 | 每副本 `tp×pp` |

核心差异：

- **TP / PP** = 同一次 `step`、同一 schedule、多 rank **协同算一份模型**。
- **DP** = 多份完整 Engine，**各算各的请求**，门面只做路由。不是 Megatron 式 NCCL DP 组。

## 2. 一步控制循环（并行无关）

`Scheduler` **不感知**并行维度，只产出 `ScheduledBatch`：

```
schedule → executor.run(sched) → read_samples → scheduler.update
```

`ScheduledBatch.to_wire()` 压成最小增量 `SchedulerOutput`，再交给执行器。  
TP/PP 下所有 rank 收到**同一份** wire；DP 下根本进不到同一个 Executor。

## 3. 三种并行分别落在哪

### 3.1 TP（张量并行）

| 层 | 做什么 |
| --- | --- |
| 控制 | 广播同一 schedule；采样 rank = 末 PP × tp0 |
| 计算 | `linear.py` / `vocab_parallel.py` 切权重；层内 all-reduce / gather |
| 调度 | 无 |

### 3.2 PP（流水线并行）

| 层 | 做什么 |
| --- | --- |
| 控制 | 同上广播；非末 stage 不采样 |
| 计算 | `qwen3` 按 `get_pp_indices` 切层；`ModelRunner` sync lockstep P2P |
| CUDA Graph | **piecewise**：recv/send 图外，本地 forward 图内 |
| 调度 | 无（不是 1F1B / 错步流水） |

`ModelRunner.run_forward`：一步 decode 再 prefill，中间张量 `hidden+residual`。

### 3.3 DP（数据并行 = 引擎副本）

| 层 | 做什么 |
| --- | --- |
| 门面 | `MPClient` round-robin；`Engine._seqs` 镜像输出 |
| 副本 | `_replica_config`：`dp_size→1`，切 `device_ids`，独立 `nccl_port` |
| NCCL | **不建 DP 组**；各副本自己的 `WORLD = tp×pp` |

因此 `EngineConfig.world_size = tp_size * pp_size`（单 Engine），  
`num_gpus = dp_size * tp_size * pp_size`（门面总卡数）。

## 4. 启动路径

| 入口 | 适用 | 说明 |
| --- | --- | --- |
| `run.py` | 单卡 / 单机 TP·PP / **DP** | spawn workers；DP 走 MPClient |
| `run_torchrun.py` | 多机 **TP×PP** | torchrun 每卡一进程；**不跑 DP** |

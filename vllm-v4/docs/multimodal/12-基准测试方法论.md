# 12 · 基准测试方法论：TTFT 如何拆分、瓶颈如何定位

> 对应代码：`vllm-v4/bench/mm_cg_suite_v4.py`
> 目标：讲清多模态推理的性能测试方法论 —— 为什么 TTFT 要拆分、图像尺寸扫描（scale sweep）怎么设计、并发测试怎么做、结果如何解读。

---

## 1. 多模态的性能指标：TTFT 是第一公民

多模态推理的**首 token 时间（TTFT, Time To First Token）**是用户体验的核心指标。与纯文本不同，多模态 TTFT 里有**一大部分是 ViT 编码**：

```text
TTFT ≈ encode_and_merge 耗时 + LM prefill 耗时
     = ViT 编码 + 散落 + MRoPE + LLM 前向
```

`bench_single` 用一个 monkey-patch 精确拆分：

```44:68:bench/mm_cg_suite_v4.py
def bench_single(eng, prompt, images, max_new: int) -> dict:
    from src.sampling_params import SamplingParams

    sp = SamplingParams(max_tokens=max_new, temperature=0.0)
    seq = eng.add_request(prompt, sp, images=images)

    vit_s = lm_prefill_s = decode_s = prefill_s = 0.0
    prefill_tok = decode_steps = 0
    first_token_s = None
    t_start = time.perf_counter()

    orig_encode = None
    if images and hasattr(eng.model, "encode_and_merge"):
        orig_encode = eng.model.encode_and_merge

        def _timed_encode(*a, **kw):
            nonlocal vit_s
            sync()
            t0 = time.perf_counter()
            out = orig_encode(*a, **kw)
            sync()
            vit_s += time.perf_counter() - t0
            return out

        eng.model.encode_and_merge = _timed_encode
```

**拆分逻辑**：
- `vit_s`：`encode_and_merge` 的总耗时（ViT 编码 + 散落 + MRoPE 都在里面）。
- `prefill_s`：整个 prefill `_run_batch` 的耗时。
- `lm_prefill_s = prefill_s - vit_s`：**LLM 部分**的 prefill（用差分算出）。
- `decode_s`：所有 decode 步的总耗时。

> **为什么要拆分？** 优化前必须先知道瓶颈在哪。如果 `vit_s` 占 TTFT 的 80%，优化 LLM prefill 意义不大；如果 `lm_prefill_s` 高，说明问题在 LLM 侧。**没有拆分的 TTFT 是黑盒，无法指导优化。**

## 2. 三个 benchmark 维度

### 2.1 图像尺寸扫描（scale sweep）

```253:273:bench/mm_cg_suite_v4.py
    # Image scale sweep
    for side in scales:
        img = load_image(str(img_path), side)
        name = f"mm_side_{side}"
        rows = [bench_single(eng, prompt, [img], args.max_new) for _ in range(args.iters)]
        report["cases"][name] = summarize(rows)
        s = report["cases"][name]
        print(
            f"  {name} ttft={s['ttft_s']*1000:.1f}ms vit={s['vit_encode_s']*1000:.1f}ms "
            f"lm_prefill={s['lm_prefill_s']*1000:.1f}ms decode={s['decode_tok_s']:.1f} "
            f"e2e={s['e2e_tok_s']:.1f} prompt_tok={s['prompt_tokens']:.0f}"
        )
```

`--scales 256,512,768` 把同一张图缩放到不同 `max_side`，看视觉 token 数如何影响 TTFT。**这是多模态最独特的 benchmark 维度** —— 纯文本没有"图像分辨率"这个变量。

**读法**：`vit_s` 随 scale 近似线性增长（token 数线性增长）；`lm_prefill_s` 也随 prompt token 数增长。**观察 `vit_cg_hits` 判断 CG 是否命中** —— 高分辨率图可能 miss budget（第 10 讲）。

### 2.2 并发/混合负载

```125:147:bench/mm_cg_suite_v4.py
def bench_concurrent(eng, jobs: list[tuple[str, list | None]], max_new: int) -> dict:
    """Fire N requests then drain; report batch wall + aggregate tok/s."""
    from src.sampling_params import SamplingParams

    sp = SamplingParams(max_tokens=max_new, temperature=0.0)
    seqs = [eng.add_request(p, sp, images=imgs) for p, imgs in jobs]
    sync()
    t0 = time.perf_counter()
    while not eng.scheduler.is_finished():
        eng.step()
    sync()
    wall = time.perf_counter() - t0
    gens = [s.num_completion_tokens for s in seqs]
    prompts = [s.num_prompt_tokens for s in seqs]
    return {
        "num_reqs": len(seqs),
        "wall_s": wall,
        ...
        "batch_tok_s": (sum(gens) / wall) if wall > 0 else 0.0,
        ...
    }
```

**并发测试用"半 mm + 半文本交替"构造**：

```278:289:bench/mm_cg_suite_v4.py
    mid = scales[min(1, len(scales) - 1)]
    img = load_image(str(img_path), mid)
    for n in conc_levels:
        # Mix: half mm, half text when n>=2
        jobs = []
        for i in range(n):
            if i % 2 == 0:
                jobs.append((prompt, [img]))
            else:
                jobs.append(("The capital of France is", None))
```

**为什么混合？** 真实生产负载是多模态 + 纯文本混合。如果只测全 mm 并发，测不出"文本请求是否被 mm 拖累"；混合测法能验证 v4 的"文本零回归"承诺（第 08 讲）。`batch_tok_s`（聚合生成吞吐）是混载下的核心指标。

### 2.3 峰值显存

```28:29:bench/mm_cg_suite_v4.py
def peak_gb() -> float:
    return torch.cuda.max_memory_allocated() / (1024**3) if torch.cuda.is_available() else 0.0
```

每次 `bench_single` / `bench_concurrent` 都记录 `peak_mem_gb`。**多模态显存比文本多两块**：ViT 权重 + EncoderCache 缓存。`torch.cuda.reset_peak_memory_stats()` 在 main 开头调用，保证计数从零开始。

## 3. 结果解读：一个典型报告的读法

```text
case            ttft     vit     lm_prefill   decode      prompt_tok
text_only       45ms     0ms     40ms         120 tok/s   30
mm_side_256     180ms    120ms   55ms         118 tok/s   300
mm_side_512     320ms    230ms   85ms         115 tok/s   520
mm_side_768     520ms    400ms   120ms        112 tok/s   800
```

**读法**：
1. `vit_s` 占 `ttft` 的 60-80% → **瓶颈在视觉编码**，下一步优化 ViT（CG 命中率、预算档位）。
2. `decode` 三档几乎不变 → 多模态对 decode 零影响 ✓（验证第 08 讲的"透明性"）。
3. `lm_prefill` 随 prompt 增长合理 → LLM 侧正常。
4. `vit_cg_hits` 若在 `mm_side_768` 掉到 0 → budget 不够大，`[64..2048]` 要扩到 4096。

**profile 字段**把中档图的 vit 占比固化到报告：

```265:273:bench/mm_cg_suite_v4.py
        if side == scales[min(1, len(scales) - 1)]:
            report["profile"]["mm_mid"] = {
                "vit_ms": s["vit_encode_s"] * 1000,
                "lm_prefill_ms": s["lm_prefill_s"] * 1000,
                ...
                "share_vit": (s["vit_encode_s"] / s["ttft_s"]) if s["ttft_s"] > 0 else 0,
                "share_lm_prefill": (s["lm_prefill_s"] / s["ttft_s"]) if s["ttft_s"] > 0 else 0,
            }
```

`share_vit` 和 `share_lm_prefill` 是**诊断性指标**：它们告诉我们"TTFT 里每部分占多少"，直接指向优化方向。

## 4. 测量纪律（benchmark 正确性）

1. **`sync()` 前后都调用**：GPU 是异步的，不 sync 测的是"发射时间"而非"执行时间"。`_timed_encode` 里 sync 保证 `vit_s` 是真实 GPU 执行时间。

```59:67:bench/mm_cg_suite_v4.py
        def _timed_encode(*a, **kw):
            nonlocal vit_s
            sync()
            t0 = time.perf_counter()
            out = orig_encode(*a, **kw)
            sync()
            vit_s += time.perf_counter() - t0
            return out
```

2. **warmup 先跑**：`main()` 先 `bench_single` 各跑一轮（`--warmup`），让 CUDA kernel 编译缓存、缓存命中稳定后再计时。**第一次跑往往包含 kernel 编译（Triton/torch.compile），不 warmup 会污染数据**。

3. **多轮取均值**：`--iters 3`，每 case 跑 3 轮 `summarize` 取均值，`peak_mem_gb` 取 max。

4. **控制变量**：`--gpu-util`（显存利用率）、`--context-len`、`--max-num-seqs` 固定，保证不同 case 可比。

## 5. 动手实验

1. 跑一遍完整 suite：`PYTHONPATH=. python bench/mm_cg_suite_v4.py --model <qwen3-vl> --image cat.jpg`，记录 `vit_cg_hits`。
2. 分别用 `--no-vit-cg` / 默认跑同一 suite，对比 `vit_encode_s` 和 TTFT，量化 CG 收益。
3. 改 `--scales 256,512,768,1024`，找到 `vit_cg_hits` 开始掉为 0 的分辨率 —— 那就是 budget 上限。
4. 去掉 `_timed_encode` 里的 `sync()`，观察 `vit_s` 是否失真（会变小，因为测的是发射时间）。

# 07 · 权重加载与算子融合：HF 权重如何映射到本地算子

> 对应代码：`src/models/qwen3_vl.py`（`load_weights`）、`src/models/qwen3.py`（`load_weights`）、`src/multimodal/vit.py`（`Qwen3VisionTransformer.load_weights`）
> 目标：讲清两个映射 —— ① 命名映射（HF 名 → 本地融合算子名）；② 分片映射（split Q/K/V → 融合 qkv；gate/up → 融合 gate_up）。

---

## 1. 为什么需要权重加载层

**你在代码里写了 `qkv_proj`（融合），但 HF 权重里是 `q_proj / k_proj / v_proj` 三个独立矩阵。** 两者参数张量形状不同，所以加载时必须做"拆开 → 按 offset 填进融合矩阵"。同理 `gate_up_proj`（融合）对应 HF 的 `gate_proj / up_proj`。

这就是"推理引擎的算子融合 vs 训练框架的独立算子"的接口问题 —— 权重加载层是两者之间的适配器。

---

## 2. 多模态模型的三个权重域

Qwen3-VL 的 HF checkpoint 里权重按前缀分域：

```text
model.visual.*                         ← 视觉塔（ViT）权重
model.language_model.*                 ← LLM 权重
lm_head.*                              ← 输出头
model.text_model.*                     ← 某些版本 LLM 用这个前缀
```

`load_weights` 分两步走：

### 2.1 视觉塔权重

```127:136:src/models/qwen3_vl.py
        hf_sd = {}
        for f in sorted(glob.glob(os.path.join(model_path, "model*.safetensors"))):
            from safetensors import safe_open

            with safe_open(f, framework="pt", device="cpu") as s:
                hf_sd.update({k: s.get_tensor(k) for k in s.keys() if k.startswith("model.visual.")})
        vc = AutoConfig.from_pretrained(model_path, trust_remote_code=True).vision_config
        self.vision_tower.load_weights(hf_sd, vc)

            self.vision_tower.vit = self.vision_tower.vit.to(device=device, dtype=dtype)
```

- 只取 `model.visual.*` 前缀的权重（先一次性读进 `hf_sd`）。
- `vision_tower.load_weights(hf_sd, vc)` 内部构造 `Qwen3VisionTransformer` 并加载（第 03 讲看过它的 `load_weights`）。
- 加载后统一 `.to(device, dtype)`。

**ViT 自己的权重加载**（`vit.py:212`）处理了两件事：前缀剥离（`model.visual.` / `visual.` / 空三种可能）和 **Q/K/V → qkv 分片拷贝**：

```222:263:src/multimodal/vit.py
        def _copy_slice(target_key: str, src: torch.Tensor, start: int, end: int) -> bool:
            if target_key not in params:
                return False
            dst = params[target_key]
            params[target_key].data[start:end].copy_(src.to(dtype=dst.dtype))
            return True

        for hk, v in state_dict.items():
            if not hk.startswith(pfx):
                continue
            nk = hk[len(pfx) :].replace("linear_fc1", "fc1").replace("linear_fc2", "fc2")

            # Split Q/K/V → fused qkv (shard copy). Check before generic path.
            if nk.endswith("attn.q.weight"):
                t = nk.replace("attn.q.weight", "attn.qkv.weight")
                loaded += int(_copy_slice(t, v, 0, hs))
                continue
            if nk.endswith("attn.k.weight"):
                t = nk.replace("attn.k.weight", "attn.qkv.weight")
                loaded += int(_copy_slice(t, v, hs, 2 * hs))
                continue
            if nk.endswith("attn.v.weight"):
                t = nk.replace("attn.v.weight", "attn.qkv.weight")
                loaded += int(_copy_slice(t, v, 2 * hs, 3 * hs))
                continue
            if nk.endswith("attn.q.bias"):
                t = nk.replace("attn.q.bias", "attn.qkv.bias")
                loaded += int(_copy_slice(t, v, 0, hs))
                continue
            if nk.endswith("attn.k.bias"):
                t = nk.replace("attn.k.bias", "attn.qkv.bias")
                loaded += int(_copy_slice(t, v, hs, 2 * hs))
                continue
            if nk.endswith("attn.v.bias"):
                t = nk.replace("attn.v.bias", "attn.qkv.bias")
                loaded += int(_copy_slice(t, v, 2 * hs, 3 * hs))
                continue
```

**`_copy_slice(target_key, src, start, end)` 是核心工具**：把 `src` 拷贝进融合矩阵的 `[start:end]` 切片。`attn.q.weight → attn.qkv.weight[0:hs]`、`attn.k.weight → [hs:2*hs]`、`attn.v.weight → [2*hs:3*hs]`。

> **为什么 bias 也要分片？** 融合 `qkv` 是 `Linear(hidden, 3*hidden)`，bias 是 `[3*hidden]`，所以 `q.bias/k.bias/v.bias` 也要按 `[0:hs]/[hs:2hs]/[2hs:3hs]` 填入。

### 2.2 LLM + 输出头权重

```138:179:src/models/qwen3_vl.py
        params = dict(self.named_parameters())
        attn0 = self.vl_model.layers[0].self_attn
        q = attn0.num_heads * attn0.head_dim
        kv = attn0.num_kv_heads * attn0.head_dim
        gate_up: dict[str, list] = {}

        for name, w in safetensors_weights_iterator(model_path):
            if name.startswith("model.visual."):
                continue
            if name.startswith("model.language_model."):
                our = "vl_model." + name[len("model.language_model.") :]
            elif name.startswith("lm_head."):
                our = name
            else:
                continue

            fused = None
            for hf, offset, size in (
                ("q_proj", 0, q),
                ("k_proj", q, kv),
                ("v_proj", q + kv, kv),
            ):
                if f".{hf}." in our or our.endswith(f".{hf}.weight") or our.endswith(f".{hf}.bias"):
                    our2 = our.replace(hf, "qkv_proj")
                    if our2 in params:
                        params[our2].data[offset : offset + size].copy_(w)
                    fused = True
                    break
            if fused:
                continue
            if "gate_proj" in our:
                our2 = our.replace("gate_proj", "gate_up_proj")
                gate_up.setdefault(our2, [None, None])[0] = w
            elif "up_proj" in our:
                our2 = our.replace("up_proj", "gate_up_proj")
                gate_up.setdefault(our2, [None, None])[1] = w
            elif our in params:
                default_weight_loader(params[our], w)
```

**命名映射**：
- `model.language_model.X` → `vl_model.X`（剥离 `model.language_model.` 前缀）。
- `lm_head.X` → 原样（本地就叫 `lm_head`）。

**分片映射（QKV）**：对每个权重名，检查是否含 `q_proj / k_proj / v_proj`，分别用 `offset` 填入 `qkv_proj` 的对应段：

```text
q_proj  →  qkv_proj[0:q]
k_proj  →  qkv_proj[q:q+kv]
v_proj  →  qkv_proj[q+kv:q+kv+kv]
```

**gate/up 是"先收集后拼接"**：因为 gate 和 up 在 HF 里是独立矩阵，本地是 `[2*intermediate, hidden]` 的融合矩阵，必须等 gate 和 up 都读到才能 `cat`：

```177:179:src/models/qwen3_vl.py
        for our2, (g, u) in gate_up.items():
            if g is not None and u is not None and our2 in params:
                default_weight_loader(params[our2], torch.cat([g, u], 0))
```

> **为什么 QKV 用"直接分片 copy"而 gate/up 用"收集后 cat"？** 因为 safetensors 迭代器是**按文件名/键顺序**流式返回的，`q/k/v` 可以在同一轮循环里分别填进同一个 `qkv_proj`（各填各的段，互不依赖）；但 `gate_up_proj` 的 gate 和 up 两半必须**按行拼接**（`cat([g,u], dim=0)`），需要先都拿到。

## 3. tie_word_embeddings 的处理（Bug 4 的背景）

```181:192:src/models/qwen3_vl.py
        if self._tie and "vl_model.embed_tokens.weight" in params:
            self.lm_head.weight.data = self.vl_model.embed_tokens.weight.data
        for p in self.parameters():
            p.data = p.data.to(device=device, dtype=dtype)
        for name, buf in self.named_buffers():
            if buf is None:
                continue
            parent, _, leaf = name.rpartition(".")
            mod = self.get_submodule(parent) if parent else self
            setattr(mod, leaf, buf.to(device=device, dtype=dtype if buf.is_floating_point() else buf.dtype))
        if self._tie:
            self.lm_head.weight.data = self.vl_model.embed_tokens.weight.data
```

- **tie 的含义**：`lm_head` 与 `embed_tokens` 共享同一份权重（Qwen 系列默认 tie）。
- 代码里做了**两次绑定**（加载前一次、全量 `.to(device,dtype)` 之后再一次）。

> **为什么需要二次绑定？** 第一次绑定在 `.to(device)` 之前，但随后 `for p in self.parameters(): p.data = p.data.to(...)` 会把 `lm_head.weight.data` **替换成一个新的张量对象**（因为 `p.data` 被重新赋值了），于是 tie 关系被打破。所以必须在 `.to` 之后重新绑定一次，确保两个模块指向同一个张量。

**这是第 13 讲会重点讨论的一个"该用更优雅方式"的点**：用 `torch` 的 `weight tying`（`nn.Parameter` 共享引用）或干脆在 `__init__` 里让 `lm_head.weight` 直接引用 `embed_tokens.weight`，可以省掉这种脆弱的二次绑定。

## 4. 与纯文本 qwen3 的权重加载差异

纯文本 `Qwen3ForCausalLM.load_weights`（`qwen3.py:191`）逻辑类似，但没有 `model.visual.*` 分支、没有 `model.language_model.` 前缀剥离，因为纯文本 HF 权重前缀就是 `model.`：

| 差异点 | 纯文本 | 多模态 |
|--------|--------|--------|
| 视觉权重 | 无 | `model.visual.*` 单独加载到 `vision_tower` |
| LLM 前缀 | `model.` | `model.language_model.` |
| `inputs_embeds` | 无 | 有 |

**核心机制（QKV 分片、gate/up 拼接、tie）完全一致** —— 所以 v4 的 `qwen3.py` 权重加载可以作为 `qwen3_vl.py` 的"最小参照"，这也是代码复用的一例（第 13 讲）。

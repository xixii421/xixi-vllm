# 01 · 全链路总览：一张图如何变成生成 token

> 对应代码：`src/models/qwen3_vl.py`、`src/engine/model_runner.py`、`src/engine/scheduler.py`
> 目标：在动手写任何模块之前，先把"一条多模态请求的生命周期"完整走一遍。

---

## 1. 一句话概括

**多模态 Multi-to-Text 的本质 = 纯文本 LLM 推理 + 一个"图像 → 视觉 embedding"的编码前级 + 三个融合动作（散落、注入、3D 位置）。**

Qwen3-VL 的 LLM 主体（`Qwen3VLModel`）和纯文本 Qwen3 几乎一模一样。多模态的全部差异，都发生在"进入 LLM 之前"和"第一层 Transformer 之前"：

| 阶段 | 纯文本 | 多模态 |
|------|--------|--------|
| 输入 | `token_ids` | `token_ids` + `pixel_values` + `grid_thw` |
| embedding | `embed_tokens(token_ids)` | `embed_tokens(token_ids)`，**把视觉 embedding 覆盖到占位符位置** |
| 位置编码 | 1D `positions` | 3D `positions`（t/h/w 三轴） |
| 中间层 | 无 | **DeepStack 注入**（前几层加视觉特征） |
| 之后 | Transformer → sampler | 与文本完全一致 |

**记住这个心智模型**：多模态不是另一种模型，而是"同一个模型 + 一层输入侧的编码与融合"。

## 2. 一条请求的生命周期

以 `engine.add_request("描述这张图片", images=[cat.jpg])` 为例，完整走一遍：

## 3. Phase 0：请求入口 —— 产出什么

`MultiModalProcessor.process()` 的产出是一个 `MultiModalInputs`：

```125:160:src/multimodal/processor.py
    def process(
        self, text: str, images: Optional[list] = None
    ) -> MultiModalInputs:
        """Process text (+ optional images) into ``MultiModalInputs``.

        Pixel hash binds the cache key to the *encoded* input (config-aware);
        prompt token ids are always rebuilt (depend on ``text``).
        """
        if not images:
            return MultiModalInputs(prompt_token_ids=self.p.tokenizer.encode(text))

        feats = [self._encode_image(im) for im in images]
        uids = [hash_image_pixels(f.pixel_values) for f in feats]
```

它产出的三样东西，分别对应后面的三个阶段：

| 产出 | 类型 | 去哪里 | 作用 |
|------|------|--------|------|
| `prompt_token_ids` | `list[int]` | 变成 `input_ids` | 文本部分的 token 序列 |
| `pixel_values` | CPU 张量 | 进入 ViT 前搬到 GPU | 图像的原始像素 |
| `image_grid_thw` | `[[t,h,w]]` | 控制 ViT 的位置与 token 数 | 决定"这张图产生多少视觉 token" |

**关键点：一张图产生多少个视觉 token，不是固定的，取决于 `grid_thw`（网格）。**

```150:165:src/multimodal/processor.py
    def _vision_tokens(self, feat: _CachedImageFeat) -> int:
        m = self._merge_size
        return feat.num_patches // (m * m)

    def _expand_image_pads(self, prompt: str, feats: list[_CachedImageFeat]) -> str:
        """Replace each single ``<|image_pad|>`` with grid-sized repeats (Qwen-VL)."""
        pad = self._image_pad
        out = prompt
        for feat in feats:
            n = self._vision_tokens(feat)
            if pad not in out:
                raise RuntimeError(
                    f"expected {pad!r} in chat template prompt for image expansion"
                )
            out = out.replace(pad, pad * n, 1)
        return out
```

这就是为什么 chat template 里只写一个 `<|image_pad|>`，实际 token 序列里要展开成 `t×h×w/merge_size²` 个——**token 序列的长度依赖图像分辨率**。这是多模态和纯文本的第一个本质差异：**prompt 长度不再是纯文本决定的，还依赖图像内容。**

> **为什么要这样设计？** Qwen 系列用的是"分辨率自适应网格"：一张大图会被切成多个 `patch_size×patch_size` 的小块（`grid_thw` 记录了 t/h/w 三个方向的块数），模型要预先知道有多少视觉 token 才能把占位符展开对。这个展开动作如果在 tokenize 之后再做，就要重新 tokenize 一次，很浪费。

## 4. Phase 1：调度 —— 多模态对调度器新增了什么

v4 的调度器在 v3 的 `mix_prefill_decode` 基础上，只加了一件事：**编码器预算截断**。

```133:160:src/engine/scheduler.py
    def _clamp_chunk_for_encoder_budget(self, seq: Sequence, chunk: int) -> int:
        """Shorten chunk so overlapping vision tokens fit the encoder budget.

        If the next image alone exceeds the budget but the cursor is already at
        that image, still schedule the image (official all-or-nothing exception)
        so the request cannot stall forever.
        """
        if not seq.has_multimodal or chunk <= 0:
            return chunk
        budget = self.encoder_compute_budget
        start = seq.num_cached_tokens
        end = start + chunk
        used = 0
        for mf in seq.mm_features:
            img_start = mf.start
            img_end = mf.start + mf.num_encoder_tokens
            if img_end <= start:
                continue
            if img_start >= end:
                break
            if used + mf.num_encoder_tokens > budget:
                # Truncate before the image when text prefix remains.
                if img_start > start:
                    return img_start - start
                # Already at the oversized image → schedule it alone.
                return min(chunk, img_end - start)
            used += mf.num_encoder_tokens
        return chunk
```

**为什么要截断？** 因为"图前文本"和"图片"不是同等成本。图前文本的 prefill 只是 LLM 计算；但"图片"意味着要跑 ViT（几十层 transformer），如果一次调度里塞了太多图片，编码器计算会瞬间爆掉延迟。所以调度器用 `encoder_compute_budget` 限制"一个 batch 里最多编码多少视觉 token"，不足就截断 prefill chunk，保证**"未编码，不过图"**。

这是多模态与调度器耦合的**唯一接口**，其余调度逻辑（KV 分配、PD mix、preempt）都和 v3 一样。

## 5. Phase 2：执行 —— encode_and_merge 是核心编排

`encode_and_merge` 是整个多模态执行的中枢，四个步骤一次完成：

```210:231:src/models/qwen3_vl.py
    def encode_and_merge(self, input_ids, seqs, device):
        """Prefill: ViT encode (window + cache) → scatter embeds → MRoPE positions."""
        text = self.vl_model.embed_tokens(input_ids)
        vis = self._encode_visual(seqs, device)
        embeds = text  # scatter in-place below; embed_tokens already returns a new tensor
        off = vi = 0
        for seq in seqs:
            cs, ce = seq.num_cached_tokens, seq.num_cached_tokens + seq.num_scheduled_tokens
            for mf in seq.mm_features:
                a, b = mf.start, mf.start + mf.num_encoder_tokens
                s, e = max(a, cs), min(b, ce)
                if s < e:
                    local = off + (s - cs)
                    src = vis[vi][s - a : e - a]
                    if src.dtype != embeds.dtype or src.device != embeds.device:
                        src = src.to(dtype=embeds.dtype, device=device, non_blocking=True)
                    embeds[local : local + (e - s)].copy_(src)
                vi += 1
            off += seq.num_scheduled_tokens
        positions = mrope_positions(input_ids, seqs, self.vision_tower.merge_size, device)
        self._mrope_module().ensure_cache_size(int(getattr(positions, "max_pos", 0)) + 1)
        return embeds, self._build_deepstack(seqs, embeds.shape[0], embeds.shape[1], device, embeds.dtype), positions
```

四个步骤：

1. **`embed_tokens(input_ids)`**：先按普通文本把整个序列 embed 了。此时占位符位置是 `<|image_pad|>` 对应的 embedding（无意义），稍后会被覆盖。
2. **`_encode_visual(seqs, device)`**：对每张图查 `EncoderCache`，miss 的图收集起来批量跑 ViT。返回 `vis`（每张图的视觉 embeddings 列表）。
3. **散落（scatter）**：遍历每个 sequence 的 `mm_features`，把 `vis[vi]` 里与当前 prefill 窗口重叠的那一段，`copy_` 到 `embeds` 的对应位置。注意 `s,e` 是 `max(a,cs) / min(b,ce)` —— **只覆盖窗口内的部分**，这是 chunked prefill 能工作的关键。
4. **`mrope_positions(...)`**：生成 `[3, N]` 的 3D 位置，并 `ensure_cache_size` 预扩展 RoPE cos/sin 表。

**返回的 `(embeds, deepstack_buffers, positions_3d)`** 就是 LLM forward 的三个输入，替代了纯文本路径的 `(input_ids, positions)`。

## 6. Phase 3：LLM —— 与文本的差异仅两处

```145:165:src/models/qwen3.py
    def forward(
        self,
        input_ids: torch.Tensor | None = None,
        positions: torch.Tensor | None = None,
        inputs_embeds: torch.Tensor | None = None,
        deepstack_input_embeds: list[torch.Tensor] | None = None,
    ):
        # Multimodal path passes pre-merged embeds (text + vision); DeepStack
        # features are added into the first few layers' hidden states.
        if inputs_embeds is not None:
            h = inputs_embeds
        else:
            assert input_ids is not None
            h = self.embed_tokens(input_ids)
        residual = None
        n_ds = len(deepstack_input_embeds) if deepstack_input_embeds else 0
        for i, layer in enumerate(self.layers):
            h, residual = layer(positions, h, residual)
            if i < n_ds:
                h = h + deepstack_input_embeds[i]
        return self.norm(h, residual)[0]
```

差异一：**输入从 `input_ids` 变成 `inputs_embeds`**（多模态时直接喂 embedding，跳过 `embed_tokens`）。
差异二：**前 `n_ds` 层加 `deepstack_input_embeds[i]`**。

除此之外，Attention（MRoPE + FlashInfer paged）、MLP、RMSNorm、残差流，全部复用 v3 的文本实现。

> **为什么视觉 embedding 要提前散落到整个序列再进 Transformer？** 因为这样 LLM 的注意力机制天然让"视觉 token"与"前后文本 token"互相 attend。如果是"编码器输出单独注入"（cross-attention 方式），就需要额外的 attention 层；Qwen3-VL 选择"扁平化序列 + 3D 位置"的方式，代价是序列变长，收益是不改 LLM 结构。

## 7. Phase 4：采样 —— 零差异

```395:399:src/engine/model_runner.py
    def _logits_for_sample(self, hidden: torch.Tensor, inputs: ModelInputs) -> torch.Tensor:
        if inputs.is_prefill and inputs.cu_seqlens_q is not None:
            last_idx = inputs.cu_seqlens_q[1:] - 1
            hidden = hidden[last_idx]
        return self.model.compute_logits(hidden)
```

采样逻辑和纯文本完全一致：取每条序列最后一个 token 的 hidden，过 `lm_head`，然后 `Sampler` 采样。**多模态的一切都在 prefill 阶段消化完了，decode 阶段对引擎完全透明**——这是 v4 的一个关键设计决策，后面第 08 讲会详细展开。

## 8. 与纯文本路径的对照表

| 环节 | 纯文本（v3） | 多模态（v4） | 差异原因 |
|------|-------------|-------------|---------|
| 输入处理 | `tokenizer.encode(text)` | + `image_processor` + 占位符展开 | 需要图像像素与网格 |
| 调度 | token 预算 | + 编码器预算截断 | 图片编码成本高且不可分 |
| embedding | `embed_tokens(input_ids)` | + 视觉 embedding 散落 | 需要把视觉特征放进序列 |
| 位置 | 1D `arange` | 3D MRoPE | 视觉 token 有 t/h/w 结构 |
| LLM | 逐层 Transformer | + 前几层 DeepStack 注入 | 增强视觉-文本对齐 |
| 采样 | sampler | 完全一致 | — |

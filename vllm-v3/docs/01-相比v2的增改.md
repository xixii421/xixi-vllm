# 相比 v2 的增改

`vllm-v3` = **v2 三面架构（控制 / 资源 / 数据）** + **高性能计算面**。

## 架构对齐（本次重构）

| 平面 | v2 | v3（对齐后） |
| --- | --- | --- |
| 门面 | `Engine` 拥有 model + KV + Scheduler + ModelRunner | 同左 |
| 控制面 | `Scheduler(kv=...)` → `(prefills, decodes)` | 同左（含 PD mix） |
| 资源层 | `KVManager`（页 + 池 + 前缀） | `memory.KVManager`（页 + FlashInfer 池 + hash） |
| 数据面 | `ModelRunner.run(prefills, decodes)` | 同合同；内部 FlashInfer / Triton / CG |
| Sequence | `from_prompt(..., block_size=)` 实例字段 | 同左 |

## 相对 v2 的性能增量

1. FlashInfer paged attention（`layers/attention_backend.py`）
2. Triton `store_kvcache` / Norm / RoPE
3. Decode CUDA Graph（`enforce_eager=False` / `--compile`）
4. pin_memory 输入 + 批量 Sampler
5. `block_size=256` + 动态 / 可覆盖 KV 池
6. **完整前缀**：`none|hash|radix`（见 `docs/03-前缀缓存Hash与Radix.md`）— radix 含 LRU evict / invalidate / dedup；hash 用 xxhash + LRU cached 页

## Chunked Prefill

与 v2 同合同：`num_cached += scheduled` → `sync_prefix`（按 `num_full_blocks` publish）；未完成 chunk 不 append；数据面可跳过无用 sample。

## 已修关键缺陷

- Prefix `can_allocate`：整页命中用 `num_tokens // block_size`（原先 `num_blocks-1` 漏掉整页）
- KV 所有权分裂：页表在 Scheduler、张量池在 ModelRunner → 统一进 `KVManager`
- 默认 `enforce_eager=True`，与 CLI 一致；CG 需显式关闭 eager

# 03 · 实测证据：瓶颈被打掉了多少

> 数字来自本仓库机器；换卡会变，**看趋势与归因**。  
> 归因请对照 [01-v2性能瓶颈](./01-v2性能瓶颈.md)。

---

## 1. vs v2：证明 P0 是算子，不是调度

同模型、同 CB 合同下（历史 Qwen3-1.7B 量级）：

| 指标 | 相对 v2 | 主要对应瓶颈 |
| --- | --- | --- |
| TTFT（短～中 prompt） | 接近或略优 | A/C/D（prefill 未 launch-bound） |
| 单流 Decode / E2E | 约 **1.7×** | **A** + D |
| Batch（如 n=8） | 约 **3.3×** | **A**（合批真正进 FI） |
| 再开 Decode CG | 再大幅上升 | **B**（小模型尤其） |

**结论**：两边都是 Continuous Batching；拉开差距的是 Attention / Graph，不是 Scheduler。

---

## 2. 开 CG：证明瓶颈 B

小模型 decode 在 `enforce_eager=False` 后可从数十 tok/s 跳到数百 tok/s。  
TTFT 几乎不靠 CG——符合「prefill 不是 launch-bound」的判断。

---

## 3. FlashInfer 旋钮：A 路径上的边际（Qwen3-8B）

`python -m bench.v3_fi_flags --model Qwen3-8B`（单流 decode 64）：

| mode | Tensor Core / non_blocking | decode tok/s |
| --- | --- | --- |
| eager 全关 | off | ~28（1.00×） |
| eager 开任一项 | on | ~33（**~1.20×**） |
| CG | 任意 | ~85（旋钮 ±1%） |

默认：`flashinfer_use_tensor_cores=True`，`flashinfer_non_blocking=True`。

---

## 4. 前缀：证明瓶颈 F 是「命中率」，不是「算子快慢」

满页二次命中（示例 0.6B）：hash/radix 二次 TTFT 接近，功能正确。  
压力下挤页（`bench.prefix_evict_compare`）：

| | hot 命中 | cold |
| --- | --- | --- |
| hash 页 LRU | 可能 **打穿 hot** | 仍在 |
| radix 树叶 | **保留 hot** | 整叶丢掉 |

→ 同算力路径下，差在少算多少 prefill。详见 [04-前缀APC](./04-前缀APC.md)。
